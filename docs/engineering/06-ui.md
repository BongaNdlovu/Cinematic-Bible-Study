# 6. User interface

**Last verified:** 18 November 2026

## Design approach

- **One look across pages:** a dark, museum-like style with gold accents. Shared stylesheets (`cinema.css`, `terms-gate.css`, `consent.css`, `desk.css`) give every page the same transitions, terms gate, consent banner and message desk.
- **Plain CSS per page:** each page has its own stylesheet (see [Project structure](03-project-structure.md#pages-and-their-scripts)). The study desk also uses Tailwind, compiled ahead of time into `css/pages/study/study-tailwind.css` (`npm run build:tailwind`). Nothing is compiled in the browser.
- **No UI framework:** components are plain DOM code, each owned by one script.

#### Reading-progress meter

The meter sits at the right end of the sticky sitting spine, so it stays in view under the top bar. It shows a bar, a percentage, and the sitting's read time (`readTime` in the sitting data, for example "16 min read"). It moves both ways: down raises it, up lowers it. It replaced the old 4px bar fixed at the top of the page, which showed the sitting number out of 11, not the reader's place.

What sets the percentage:

| Situation | Percentage |
|---|---|
| Reading (audio not playing) | Place in the whole sitting. Scrolling the page counts. In book view each page turn also counts, as one book height. The questions and the proof task count too, one screen height each, and only when answered. So the end of the page shows 100% only once every question and the proof task are done. |
| Listening (lesson audio playing) | Where the audio is: `currentTime / duration`. The label changes to "N min listen" (the recording's length, rounded). |
| Audio paused or ended | Back to the reading percentage and "min read". |

Decisions and their reasons:

- **In the spine, not in a new bar.** The spine is already sticky, already set in the mono capitals the meter uses, and already themed for all four reading themes. The meter uses `currentColor`, so it follows each theme without its own colour rules.
- **Audio drives it while playing.** The read-along already scrolls the page with the voice, but a listener may scroll away. The audio position stays right either way.
- **The questions and the proof task count.** They open in the step-by-step question dialog, not on the page, so the page alone could reach 100% with the work unfinished.
- **Updates are batched to one per frame** (`requestAnimationFrame`). A hidden browser tab gets no frames, so the meter only updates while the page is visible.
- **Missing parts stop the meter, not the page.** `read-meter.js` works only when `#read-meter` and its fill, percentage and label are all in `study.html` (`hasMeter`). If one is missing, the meter stays still. Before 18 November 2026 only `#read-meter` was checked, so a missing part threw a page error each time the meter updated.

At 1440px the spine keeps its height. Where the spine wraps (measured at 1024px) the meter takes its own row, and the spine grows from 47px to 81px. On a 375px phone the meter is a single row, and the spine grows from 111px to 130px.

## UI rules worth keeping

- A late server reply must never change a screen the reader has already left. Guard every async callback with a ticket or generation check. The quiz, task-flow, report builder and map flight all use this pattern.
- A lock is released only by the request that took it. The message desk's `lock()` returns a token, and `unlock(key, token)` ignores any other token.
- When one value drives several displays (type, label, highlight), derive them all from one table rather than separate thresholds.
- A message that promises a retry must only appear while a retry is really scheduled.
- A button's disabled state must check the same lock key that its action takes (see `lockKeyFor` in `js/features/desk.js`).
- Anything that runs on its own (playback, tours) must have a way to stop it, and a reader's own choice stops it.
- Each layer owns its own Escape. A layer that is not on top must not react.
- Styles live in stylesheets. No script creates a `<style>` element (since 16 November 2026). A per-page value goes on an element as a custom property, as `js/pages/study/book-open.js` does on `<html>`.
- A class name used by two components must be scoped. The reader prompt cards (`div.insight-card`, children of `<body>`) and the Insights tab cards (`article.insight-card` in `#panel-insights`) share a name. Until 16 November 2026 the prompt's rules also turned the tab's three cards into fixed boxes at the top of the screen. `css/features/insight-card.css` now matches only `body > .insight-card` (written with `:where()`, so the specificity is unchanged), and `tools/verify/verify_insight_cards.mjs` checks it.
- `!important` is not added to win a fight. See [the inventory](important-inventory.md) of the 314 that exist.
- Destructive buttons ask twice ("Remove for you?"). After a failure they go back to their normal state.
- Never show a "write a new one" form when the site could not check whether one already exists.
- Full-screen diagrams (mind map, table, comparison, timeline) put `position: fixed; inset: 0` on the block itself, not the Fullscreen API. This escapes any ancestor's overflow, needs no user gesture, and keeps Escape in the page's own layer order. The Fullscreen API would hand Escape to the browser.
- Layers stack in this order. A new layer takes a place in this ladder:

| z-index | Layer | Code |
|---|---|---|
| 72 | Survey and insight cards | `.insight-card` in `js/features/analytics.js` |
| 180 | Full-screen mind map and diagrams | `.mm.is-full` in `css/pages/study/parts/07-mindmap.css`, `.chain.is-full` in `css/pages/study/parts/08-diagram-shell-and-print.css` |
| 220 | Story reader | `.story-read` in `css/pages/study/parts/04-story.css` |
| 240 | Reference panel opened from a full-screen layer | `html.dfx-cite-open .sheet-verify` in `css/pages/study/parts/09-diagram-fullscreen.css` |

- Code comments state a constraint, a contract with another file, or a reason that is not obvious, in a few lines. History, design decisions and who found what belong in this handbook and the changelog, not in comments.
