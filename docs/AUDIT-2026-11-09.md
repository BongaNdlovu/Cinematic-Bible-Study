## Verdict

**Ready with conditions.** The security core is strong: every table has row-level security, anonymous requests cannot read anyone's data, grading and certificates are decided on the server, the headers are strict, and users can download and delete their own data. What holds it back from serving many users is operational, not code: there are no database backups, sign-up emails are capped at 2 an hour, operator access to all learner data rests on one Google password, and the latest fixes are not live.

Fix C1 and H1–H3 before inviting a large audience. M1–M4 should follow soon after.

## Findings

### Critical

**C1. The database has no backups.**
- Evidence: `docs/ARCHITECTURE.md:132` says the Free plan has no project backups. The only export is `backups/exhibit-progress-2026-09-26T225404Z.json`, which covers 1 of 17 tables (`tools/export-exhibit-progress.sql` reads `public.exhibit_progress` only). It lives only on the operator's laptop, because `backups/` is in `.gitignore:48`. No restore has ever been run.
- Failure: if the project is deleted, corrupted, or hit by a bad migration, every account, note, certificate, review and message is gone for good.
- Fix: in progress in a separate session (encrypted daily dump of `public` + `auth` to Cloudflare R2, plus an automated restore drill). Supabase Pro adds 7 days of platform backups on top of that.

### High

**H1. Auth email is capped at 2 messages an hour, and email sign-up is on.**
- Evidence: `docs/ARCHITECTURE.md` Auth table, "Emails sent: 2 / hour" (confirmed 18 Oct 2026). Live `GET /auth/v1/settings` shows `email: true`, `disable_signup: false`, `mailer_autoconfirm: false`, so every email sign-up needs a confirmation email.
- Failure: if a class of 30 signs up by email in the same hour, 28 never get a confirmation link. Password-reset emails are capped the same way. Commit `5417d2d` puts Google first, which helps, but it isn't live yet (see H3) and email is still offered.
- Fix: set up custom SMTP in Supabase Auth (for example Resend, Postmark or SES) and raise the email rate limit. Or switch off email sign-up until that's done.

**H2. Operator access to all learner data needs only a Google password.**
- Evidence: `tools/supabase-reviews.sql:46-64`. `is_review_moderator()` asks for `aal2` only when the account already has a verified MFA factor (`not exists (... mfa_factors ... 'verified') or aal = 'aal2'`). A moderator can read every profile (`supabase-insights.sql:146`), all progress (`supabase-progress.sql:42`), all study data, all surveys, all events, and graduate emails (`exhibit_graduates`). The privacy page (`privacy.html:145`) says the background answer is special personal information under POPIA, because it concerns religious belief.
- Failure: if someone phishes or reuses the moderator's Google password, they can export every learner's email and religious-background answer.
- Fix: require `aal2` for moderators without exception, and enrol a second factor before the change goes in. Also confirm 2FA on the Supabase, Cloudflare, GitHub and Google owner accounts (**not checked**).

**H3. The fixes from the latest review are not live.**
- Evidence: `git status -sb` shows `master...origin/master [ahead 3]`. Those 3 commits are `dc18eeb` (audit bugs in sync, deploy, study content and gallery), `9f2872b` and `5417d2d`. The last production deploy ran from `4add22d`.
- Failure: the sync bugs fixed in `dc18eeb` can still hit users on the live site today, and the commits exist on only one disk.
- Fix: push `master`. CI runs lint, the unit tests and `npm test`, then deploys and runs the smoke test.

### Medium

**M1. The Free plan is not built for production traffic.**
- Evidence: Supabase pauses Free projects after low activity over 7 days. Free projects run on shared CPU with 500 MB RAM and a 500 MB database. Paid projects are never paused. [Project Pausing](https://supabase.com/docs/guides/platform/free-project-pausing), [Pricing](https://supabase.com/pricing).
- Failure: a quiet week, such as a school holiday, pauses the database, and every sign-in and save fails until someone restores it by hand.
- Fix: move to Pro before growth. That also covers part of C1.

**M2. Outage detection runs every few hours, not every 15 minutes.**
- Evidence: `.github/workflows/health.yml` asks for `*/15 * * * *`. `gh run list` shows the last four runs at 19:53, 23:31, 02:59 and 11:19 UTC, gaps of 3.5 to 8 hours. GitHub delays scheduled workflows.
- Failure: the site can be down for most of a day before anyone gets an alert.
- Fix: add an external uptime monitor (for example UptimeRobot, Better Stack or Cloudflare Health Checks) on `/` and on the Supabase auth health URL.

**M3. The privacy page will need to mention backup copies.**
- Evidence: the Retention table (`privacy.html:209-221`) says account data is "Deleted with your account". After C1, a deleted user's rows will remain in encrypted backups until those backups expire.
- Fix: add a row such as "Backup copies: kept up to 30 days, then overwritten". Make sure a restore doesn't bring back accounts that were deleted, for example by keeping a deletion log and running it again after any restore.

**M4. No load test, and the docs about page rate limits are about to be wrong.**
- Evidence: `9f2872b` removes page views from Functions (the live `_routes.json` lists only operator paths, `/csp-report` and `/__rate`). `docs/ARCHITECTURE.md:134` still says ordinary pages share 240 reads a minute.
- Fix: update the doc once it's pushed. Before a big launch, run a short load test against a staging copy, not production (**not checked** here, by agreement).

## What passed

**Data access (live, with the public key and no session)**
- 13 of 17 tables returned `401 permission denied`: certificates, help_notes, help_replies, migrations, moderators, notice_receipts, notices, password_failures, quiz_keys, quiz_passes, reviews, surveys, write_slots.
- 4 returned `200 []` (events, profiles, progress, study_data). The anon role has SELECT on those tables, and RLS filtered every row out.
- These RPCs denied anonymous callers: `exhibit_graduates`, `exhibit_help_inbox`, `exhibit_help_mine`, `exhibit_shows_authenticator`. `exhibit_public_reviews` returns approved reviews only, without user ids or emails (`supabase-reviews.sql:84-87`).
- The OpenAPI schema needs a secret key (`401 Secret API key required`).

**Schema (static)**
- RLS is enabled on all 17 tables (each table's `enable row level security` line was found in `tools/supabase-*.sql`).
- Own-row policies check `auth.uid() = user_id` on both `using` and `with check`.
- `exhibit_moderators`, `exhibit_quiz_keys`, `exhibit_quiz_passes` and `exhibit_certificates` have every grant revoked.
- Certificates need 11 sittings passed according to the server-side `exhibit_quiz_passes` table (`supabase-pending-migrations.sql:253-268`), not progress the browser can write.
- Quiz answers are graded by `verify_quiz_answer`, and the correct index varies (sitting 0: 1, 3, 0, 2, 1). That fixes the "always 0" finding from the 24 Sep audit.
- A heuristic scan found no `security definer` function missing `set search_path`.
- `exhibit_delete_my_account()` deletes the user's rows from 11 tables, strips their id from events, and deletes the `auth.users` row (`supabase-pending-migrations.sql:463-511`).

**Auth (live settings)**
- Anonymous sign-ins are off.
- Email confirmation is required.
- Google and email are the only providers.
- Password minimum is 12 characters, and sign-in is limited to 5 attempts per 5 minutes (`docs/ARCHITECTURE.md`).

**Site (live)**
- `/` serves the CSP, `Strict-Transport-Security` (with preload), `X-Frame-Options: DENY` and `nosniff`.
- `/backups/`, `/docs/…`, `/package.json`, `/.env.local` and `/tools/…sql` all return 404.

**Client**
- Sentry: `dataCollection.userInfo: false`, replays at 0, off on local hosts, and the feedback widget loads only with analytics consent and when Do Not Track / Global Privacy Control are off (`js/shared/sentry.js`).
- User-written text in `desk.js`, `account.js`, `insights.js`, `sid-report.js` and `shelf.js` goes through `textContent` or an escape helper. 104 `innerHTML`/`insertAdjacentHTML` sites exist; the ones that render user data were sampled, not all 104.

**Tests and delivery**
- `npm run test:unit`: 48 of 48 passed.
- `npm test` (25 verify scripts, including Playwright end-to-end): exit 0.
- `npm audit --omit=dev`: 0.
- CI deploys only from `master`, only after the tests pass, then smoke-tests the live site and opens an issue on failure.
- `npm run rollback` restores the previous production deploy.

**Privacy**
- The POPIA/GDPR policy names a lawful basis for each purpose.
- Users can download their data as JSON (`account.js:355`) and delete their own account.
- `pg_cron` deletes anonymous data after 90 days (`supabase-anon-retention.sql`).

**Earlier audits**
- The `server.js` range crash (8 Sep, C1) is gone; the file no longer exists.
- The Tailwind CDN is no longer in the CSP.
- The answer-index pattern is fixed.
- The 8 Nov review's 7 bugs are committed in `6168ec6` and `dc18eeb`, but `dc18eeb` isn't live (H3).
